# BRIEF — mercurius-messenger

Единый интерфейс канала связи с нормализованной моделью входящих и исходящих сообщений на AMPHP v3, адаптер Telegram
Bot API (webhook и long polling) и канал WebSocket. Новые каналы — REST API, Slack, Bitrix24 — добавляются адаптерами.
Пакет — часть Меркурия (`opencck/mercurius`), подключается сабмодулем в `packages/messenger/` и не зависит от
приложения.

## Назначение и границы

В пакете:

- интерфейс `Channel` и необязательные интерфейсы возможностей (темы форума, опросы, контакты, геоточки);
- неизменяемые типы входящего сообщения, нажатия кнопки, поста канала, изменения членства, вложения, результата отправки;
- очередь по чатам (`ChatDispatcher`), дедупликация обновлений, разбиение длинного текста;
- адаптер Telegram: клиент Bot API, разбор `Update`, long polling, обработка тела webhook, перевод Markdown в HTML;
- адаптер WebSocket: кадры JSON, очередь отправленного без клиента, маршрутизация чатов по приставке.

В приложении остаётся:

- HTTP-сервер, маршрут webhook и регистрация вебхука (`APP_URL`, `TELEGRAM_MODE`); пакет обрабатывает только тело;
- сервер WebSocket, проверка ключа (`/apikey`), привязка соединения к участнику; пакет не зависит от библиотеки WebSocket;
- что делать с сообщением: доступ, участники, агентский цикл (`MessageHandler` реализует приложение);
- путь к Telegram (прокси, VLESS — пакет `connectors`) и чтение файлов локального сервера Bot API (замыкание `localFile`);
- хранилище принятых `update_id` (`seen_updates`), которое `Deduplicator` получает замыканием `firstSeen`;
- ответ длиннее восьми частей файлом и восстановление недоставленных ответов.

## Устройство

| Класс / каталог | Что делает |
|-----------------|------------|
| `Channel`, `Capabilities` | Отправка, правка (с ровно этими кнопками), ответ на нажатие, файлы и медиа, скачивание вложения с пределом, удаление, выход из чата, «печатает»; флаги `canEdit`, `maxMessageLength`, `supportsButtons` |
| `ForumChannel`, `PollChannel`, `ContactChannel`, `LocationChannel` | Необязательные возможности; проверка — `instanceof`; неудача — false или null, без исключений |
| `RoutingChannel` | Один `Channel` для ядра: чаты с приставкой (`ws:`) уходят своему каналу, остальное — каналу по умолчанию |
| `IncomingMessage`, `Attachment`, `AttachmentKind` | Нормализованное входящее: чат, автор, текст, тема, ответ, правка, флаг бота, вложения и вложения сообщения, на которое ответ |
| `OutgoingMessage`, `ParseMode`, `Button`, `MediaKind` | Исходящее: текст, разметка (`plain`, `markdown`, `html`, `markdown_v2`), тема, кнопки (данные до 64 байт), вид медиа |
| `IncomingCallback`, `IncomingPost`, `IncomingMembership` и их `*Handler` | Нажатие кнопки, пост канала, добавление и удаление бота; обрабатываются в обход очереди чата |
| `MessageHandler` | `handle(IncomingMessage)` — реализует приложение |
| `SendResult`, `SendErrorKind` | Итог отправки: id, id продолжений, вид ошибки (`too_long`, `bad_format`, `forbidden`, `not_found`, `rate_limited`, `transient`, `unknown`), `retryAfter` |
| `ChatDispatcher` | Чаты параллельно, один чат по порядку; очередь чата до 100; склейка текста, разрезанного клиентом (`splitDelay`, `splitThreshold` 4000) |
| `Deduplicator` | LRU последних id обновлений (4096) и, по желанию, внешнее хранилище через `firstSeen` |
| `TextSplitter` | Разбиение по абзацам и строкам с сохранением блоков кода; длина в единицах UTF-16 |
| `Telegram/TelegramApi`, `TelegramException` | Тонкий клиент Bot API: таймаут 30 с, `baseUrl` для локального сервера, ошибки с `SendErrorKind`, токен не попадает в ошибки |
| `Telegram/TelegramChannel` | `Channel` для Telegram: части по 4096, повтор плоским текстом при отказе разметки, не чаще раза в секунду на чат, окно flood после 429, правка без изменений — пустая операция |
| `Telegram/UpdateParser` | `Update` → входящее сообщение, нажатие, пост или членство; боты, посты и правки — только если включены |
| `Telegram/LongPolling` | Цикл `getUpdates`: offset, дедупликация, снятие вебхука, паузы 1–60 с при ошибках, `stop()` |
| `Telegram/WebhookProcessor`, `WebhookRequestValidator` | Тело webhook и проверка секретного заголовка за постоянное время; обработчики работают после ответа 200 |
| `Telegram/MarkdownToTelegramHtml` | Обычный Markdown моделей в HTML Telegram, в том числе недописанный текст потока |
| `Websocket/WebsocketChannel`, `Connection` | Канал WebSocket: личный чат `ws:<имя>` у каждого клиента, очередь до 200 кадров без клиента, входящие файлы в памяти до 64 МБ |

## Решения

- **Один `Channel` для ядра.** Каналы связи — обязательная абстракция: ядро не знает Telegram, второй канал
  подключается через `RoutingChannel`.
- **Обязательное — минимум, остальное — необязательными интерфейсами:** ядро проверяет возможность и без неё
  отвечает текстом, канал не обязан притворяться.
- **Ошибки отправки — значением `SendResult`, а не исключением:** вызывающий решает, повторить, разрезать или сдаться,
  по `SendErrorKind` и `retryAfter`.
- **Чаты параллельно, чат по порядку, очередь ограничена:** ответы одному человеку не перемешиваются, флуд не съедает память.
- **Нажатия, посты и членство — в обход очереди чата:** кнопка подтверждения не ждёт, пока закончится запуск.
- **Склейка разрезанного текста:** клиент Telegram режет длинный текст на 4096; часть от 4000 символов ждёт продолжения
  (как `_text_batch_delay_for` hermes), короткие не ждут.
- **Длина — в UTF-16:** так считает Telegram.
- **Разметка с отступлением:** при отказе Telegram разобрать HTML текст уходит без маркеров, ответ не теряется.
- **Темп отправки в канале:** не чаще раза в секунду на чат, правки склеиваются, после 429 — окно ожидания.
- **Дедупликация с внешним хранилищем:** повторная доставка после перезапуска не запускает агента второй раз; сбой
  хранилища пропускает обновление.
- **Long polling переживает любую ошибку:** пишет её в журнал и опрашивает снова с растущей паузой.
- **Секреты:** токен бота и секрет webhook — `#[\SensitiveParameter]`, в ошибки не попадают.
- **Образец — адаптер Telegram hermes;** взятое отмечено ссылками `ref:` в коде (`MarkdownToTelegramHtml`,
  `ChatDispatcher`, `LongPolling`, `TelegramChannel`).

## Проверки

- `composer check` — PHPUnit, PHPStan (уровень `max`), Psalm (`errorLevel="1"`); юнит-тестам сеть не нужна.
- `composer test-integration` — группа `integration`: настоящий Bot API с `TELEGRAM_BOT_TOKEN`; запускается на сервере
  проекта, не в CI.
- CI (`.github/workflows/ci.yml`): одна задача, PHP 8.2 (другая версия — вручную через `workflow_dispatch`), push и
  pull request в `master`, изменения только в `*.md` не запускают, `cancel-in-progress`, кеш Composer и анализаторов,
  10 минут; без сети и секретов — группа `integration` в CI не входит.
